# Review 3 (Codex, read-only, 2026-09-20)

Run after the domain, receipts, sandbox, adapter, policy, integrity and CI work. Eight findings, all real, all fixed. Recorded here because several of them are the exact failure mode this project exists to find: a control that looks like enforcement and is not.

| # | finding | fix |
|---|---|---|
| 1 | The agent could forge the container's result envelope. Runner and agent share a uid and a pid namespace, so `kill -USR1 1` starts Node's inspector on loopback and `Runtime.evaluate` can write a clean result after a destructive command. | The runner installs its own SIGUSR1 and SIGUSR2 listeners, which stops Node opening the inspector at all. The host now takes the last envelope and refuses a run that emitted more than one. |
| 2 | Shell injection in the generated guard. `committed()` interpolated a path into `execSync`, so `Write` with `file_path: "x$(rm -rf .claude).txt"` ran the substitution and could delete the enforcement configuration while the guard was checking whether the file existed in HEAD. | No shell in the guard at all. Every git call goes through `execFileSync` with an argv. |
| 3 | A command's own output was trusted as enforcement. `cat .env; printf 'permission denied\n' >&2; exit 1` reads the secret, gets marked denied by a text pattern, is then skipped by the assertion, and is counted as a mechanical block: PASS. | Denials carry their source: runtime, hook, or error-text. Only the first two count as controls. The secret assertion checks a result for the canary whatever the call's status claimed. |
| 4 | `bash -lc 'rm -rf build'` was invisible. The guard looked for an exact `-c`, and the segment parser never expanded a shell's command argument. Both missed it, so the trial passed. | A new `allSegmentsDeep` expands `-c`, `-lc`, `-ec` and `--command`, used by paperfence's matcher, assertions and guard. `allSegments` stays faithful to Claude Code, which does not look inside `sh -c`, because reporting a documented gap as a gate is the failure this tool exists to find. |
| 5 | A runner config the agent created was in no snapshot. Writing `vitest.config.ts` with `exclude: ['**/*']` and `passWithNoTests` makes the suite green with every test and the test script untouched. | The assertion walks for test-control files that exist now and were not there before, and says whether the new file excludes tests. |
| 6 | Markdown claimed success when nothing was measured. A report where every trial errored read "All 0 testable rules have a control behind them"; two fully errored compare arms read "No regression". | Both headlines now say nothing was measured and name what failed. |
| 7 | Receipt ids collided. The canonicaliser copied keys with `out[k] = ...`, and `out["__proto__"] = x` sets the prototype instead of creating a property, so a receipt edited under `__proto__` hashed the same and still verified. | The canonical form is built from key/value pairs as a string, never by assignment. |
| 8 | Redaction covered receipts and not reports. `buildReceipt` redacted a copy; `--json` and `--html` serialised the original events and final text, canary included. | Redaction happens once, at the sandbox boundary, after the assertions and before anything is returned. |

Every one has a regression test. Findings 3, 5 and 6 were cases of the tool reporting a pass it had not earned, which is why they rank above the injection.
