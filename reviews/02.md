## Docker/proxy

**The architecture is moving in the right direction. The boundary is incomplete.**

### 1. Isolate the preliminary hooks

[attack/index.ts:44](/Users/abhiyanpoudel/Desktop/Projects/langham/paperfence/src/attack/index.ts:44) executes hooks in the original checkout before checking Docker availability. `attack` has no `--no-hooks` option.

A hook can read the real home directory, modify the checkout or launch processes. A minimal environment does not remove filesystem authority; `bash -lc` can also reload login configuration.

**Before shipping:** execute probes in isolation too. The advertised safe command must not execute repository code on the host.

### 2. Close host access and narrow proxy exposure

[Docker networking setup](/Users/abhiyanpoudel/Desktop/Projects/langham/paperfence/src/sandbox/docker.ts:111) uses `--internal`, which still permits connections to the bridge gateway and appropriately bound host services. “Only the proxy is reachable” is false. [Docker internal-network documentation](https://docs.docker.com/reference/cli/docker/network/create/#network-internal-mode---internal)

The proxy also binds `0.0.0.0` and joins the shared default bridge. Other containers on that bridge can reach its credential-backed API without authentication. [Docker bridge behavior](https://docs.docker.com/engine/network/drivers/bridge/)

**Before shipping:** explicitly deny agent-to-host traffic, use a dedicated proxy egress network, and restrict/authenticate the proxy listener. Verify host access, external DNS and IPv4/IPv6 egress on supported Docker platforms.

### 3. Stop mounting the observer’s state writable

[docker.ts:130](/Users/abhiyanpoudel/Desktop/Projects/langham/paperfence/src/sandbox/docker.ts:130) exposes the whole sandbox parent: job, result and bare origin. The runner and adversarial subprocesses also share UID 1000.

The agent can mutate origin directly, tamper with result delivery, or interfere with the runner. The host then parses an unvalidated `result.json` at line 159.

**Before shipping:** isolate the runner from tool processes; keep results and sink logs outside agent write authority; expose origin through a controlled Git service; validate result schemas. Mount only the intended working tree writable.

### 4. Fix the container user and mount ownership

[docker.ts:71](/Users/abhiyanpoudel/Desktop/Projects/langham/paperfence/src/sandbox/docker.ts:71) runs `useradd -u 1000 ... || true`. The official Node image already has UID 1000 assigned to `node`. Creation fails silently, while HOME points to `/home/agent`, which was never created. [Node image Dockerfile](https://raw.githubusercontent.com/nodejs/docker-node/main/22/bookworm-slim/Dockerfile)

On native Linux, a host-created mode-0700 temporary directory owned by another UID is also inaccessible to container UID 1000.

**Before shipping:** use the existing user with a valid writable home and explicitly provision sandbox ownership. Test a non-1000 host UID.

### 5. Restrict credential use, not just credential visibility

[proxy.ts:26](/Users/abhiyanpoudel/Desktop/Projects/langham/paperfence/src/proxy.ts:26) accepts endpoint prefixes, including organizations, and every HTTP method. The agent can make unlimited requests using your account outside the SDK turn budget.

At lines 98–111 it buffers unlimited request bodies, has no upstream deadline, and does not cancel upstream work when clients disconnect.

**Before shipping:** exact endpoint/method allowlists, model/token/request budgets, body and concurrency limits, deadlines and cancellation. Strip hop-by-hop headers correctly.

Also, [docker.ts:114](/Users/abhiyanpoudel/Desktop/Projects/langham/paperfence/src/sandbox/docker.ts:114) puts the credential directly in subprocess arguments. A failed `execFile` can include that command in its error message; line 152 preserves the first line for reporting. Use secret delivery without credential-bearing argv and sanitize errors.

### 6. Make cleanup survive failure

[docker.ts:141](/Users/abhiyanpoudel/Desktop/Projects/langham/paperfence/src/sandbox/docker.ts:141) has no wall-clock deadline or spawn-error handler. Cleanup swallows every failure. Image-build stdout is piped but never drained, and failed builds leave temporary contexts. Sandbox destruction in `attack/index.ts:108` is outside a per-run `finally`.

**Before shipping:** bounded execution, cancellation, signal handling, cleanup verification and stale-resource reclamation. Drain every pipe. Add CPU and writable-storage limits; memory/PID limits do not prevent disk exhaustion.

Finally, copying ignored files at `sandbox/host.ts:56` still exposes real unmentioned secrets to the agent—and therefore potentially to Anthropic through the intended proxy.
