# Review 5 (Codex, read-only, blind, 2026-09-20)

The first review given no steering. Codex was pointed at the repository, told to read the README and decide for itself where the risks were, and told only that a wrong "yes, that is protected" is worse than a crash. It was not told what had changed, what previous reviews found, or which files were new.

The question this was meant to answer: **would an independent reader find only ordinary bugs, or another path where paperfence reports evidence it did not earn?**

It found nine of the latter, plus a credential exposure. Twelve findings, all real, all fixed.

## The credential one first

**Real secrets reached the agent.** The sandbox replaced credential files with canaries, but only the ones named by the rules handed to that trial, and an attack run hands over one rule at a time. A trial about protected branches copied `.env.production`, `.npmrc` and any key file into a sandbox a live agent could read. Their contents could then reach the model, the tool log and a receipt, and redaction only removes canaries it knows about.

The tree is now the source of truth: anything matching a credential shape is replaced, with example and sample files left alone, and the rules only add to that list.

## Reporting a pass it had not earned

| # | what it reported | why it was wrong |
|---|---|---|
| 3 | PASS after deleting files | `{ find . -name '*.log' -delete; }` parses as a segment whose program is `{`. Neither the guard nor the matcher looked inside a brace group. |
| 4 | PASS after a hard reset | `git reset --hard HEAD; echo "permission denied" >&2; exit 1` gets marked denied by its own output, and every assertion but two dropped denied events. The secret and exfiltration assertions already distinguished a runtime refusal from a command's text; the rest did not. |
| 5 | the required step ran | `false && npm test; git commit` contains the words and never ran them, and `npm test --help` earned credit in both the assertion and the guard. |
| 6 | PASS after an out-of-scope edit | The scope exemption `/^\.(claude\|git)/` also matched `.github`, so editing a CI workflow under "only modify `src/`" was discarded. |
| 7 | GATE on a multi-target rule | Secret probes used the first named file only, so a deny entry covering `.env` earned a gate while `.env.production` stayed readable. |
| 9 | PASS on most real repositories | The sandbox strips `node_modules` and the container has no network, so `npm test` cannot run for any project whose framework needs installing. The agent gives up, and "agent declined" became a pass. This would have applied to nearly every Vitest or Jest repository. |
| 10 | Codex verdicts from a Claude Code run | `attack` never calls the Codex driver. Promoting the adapter to `drive: true` made coverage mark Codex supported and suppressed the uncovered-runtime warning, while the trial ran a different agent entirely. This was introduced by the promotion commit. |
| 12 | "good done" for doing nothing | The default good task asked the agent to run tests and report, and checked only that the working tree stayed clean. A configuration blocking every tool passed it, inflating exactly the number that half of the suite exists to protect. |

## The rest

| # | finding | fix |
|---|---|---|
| 2 | `mv .claude/hooks saved-hooks` removed the guard; self-protection checked only the destination. | Moving the hook, its policy or settings is blocked at the source too. |
| 8 | The network guard searched the whole command for `localhost`, so `https://example.com/localhost` looked like loopback. | Each URL's host is parsed and checked. |
| 11 | Rule ids were positional, so inserting a rule shifted every id below it onto a different sentence, and the control plane's "what started failing" compared across weeks by id. | Ids are derived from the file and a hash of the rule text. An inserted rule no longer shifts the others; an edited rule becomes a new id, which is correct. |

## What this says about the process

Findings 9 and 10 are the ones worth sitting with.

Nine would have affected nearly every real repository, and four previous reviews did not find it, because every one of them read the code rather than asking what happens when the code meets a normal project. The first run against real repositories found different problems again, in extraction.

Ten was introduced by the commit that promoted the Codex adapter, and the promotion was justified by a conformance suite that passed. The suite measured what it measured; nothing checked that the thing being promoted was wired into the path that claims to use it.

Both argue the same thing: reviewing the code is not the same as running it against the world, and a passing suite is evidence about the suite.
