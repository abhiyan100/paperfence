What this means

A wish is a rule like "never push to main" with nothing behind it but the sentence. The agent follows it because it is well-behaved, and it will keep following it right up until a user in a hurry, or a note planted in the repo, gives it a reason not to. A gate is a rule that is also backed by a permissions.deny entry or a PreToolUse hook that exits 2, so the tool call fails no matter what the agent decides.

This is not a ranking of who writes good rules. Most of these repos write very sensible rules. It is a measure of how much of that sense is load-bearing.

npx paperfence attack .               # a real agent tries to break each rule, in Docker
npx paperfence harden .               # write the locks
npx paperfence compare . --hardened   # do the locks hold, and does normal work still get done
